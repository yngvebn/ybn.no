# Copy style

Write about what the project does, what happened, and who did the work. Let the details supply the humour. Keep the author's supplied headline, tagline and philosophy; they are deliberate choices for this site.

## Common habits to edit out

1. **Inflated vocabulary.** “Leverage,” “delve,” “unlock,” “elevate,” “seamless,” “transformative,” “cutting-edge.” Use the verb that describes the action.
2. **Empty positioning.** “Where technology meets creativity,” “at the intersection of…” Name the thing and say what it does.
3. **Manufactured contrasts.** “Not just X, but Y,” “this isn't about X; it's about Y.” State the relevant fact directly.
4. **Repeated groups of three.** Three fragments, benefits or abstract nouns in every section. Use the number of points the subject needs.
5. **Staccato emphasis.** “A phone. A browser. A possibility.” Join related facts into a sentence.
6. **Staged revelations.** “Here's the thing,” “the real magic,” “what happened next.” Tell the reader what happened.
7. **Question-and-answer hooks.** “The result? A new tab.” Write the sentence without the staged question.
8. **Stock metaphors.** Journeys, tapestries, ecosystems, threads, bridges, second lives and machinery underneath. Use concrete names where the metaphor adds no information.
9. **Personifying software.** An oracle “learned to say yes,” an idea “wanted to survive.” Say who changed what.
10. **Forced punchlines.** A clever final sentence on every description. Keep humour where the facts support it; leave the rest alone.
11. **Manufactured self-deprecation.** Calling every small project absurd, unreasonable or over-engineered. The site's tagline already does that work.
12. **Invented origin stories.** “I just wanted…” or “it started with a simple question” without the author's recollection. Describe the implementation or ask the author.
13. **Small features inflated into lessons.** A pairing API does not need a conclusion about human connection.
14. **Vague significance.** “Something useful,” “what comes next,” “a deeper understanding.” Specify the information, action or relationship.
15. **Decorative qualifiers.** “Genuinely,” “remarkably,” “incredibly,” “very,” “particularly.” Keep them only when they add a defensible distinction.
16. **Canned transitions.** “Importantly,” “ultimately,” “it's worth noting,” “in today's world.” Usually delete them.
17. **Repetition across sections.** A headline, introduction, body and conclusion making the same point. Give each part a job or remove it.
18. **Unneeded disclaimers.** Announcing all the claims the page is not making. State uncertainty where it affects the story; avoid unsupported claims in the first place.
19. **Generic calls to action.** “Discover,” “explore,” “dive into,” “unlock.” Prefer “Play NoteQuest,” “Read about this project,” or “View the repository.”
20. **Unsupported praise and outcomes.** “Powerful,” “innovative,” “successful,” “beloved,” or implied adoption. Describe observable behaviour and verified history.
21. **Over-explained connections.** Telling readers that every project reveals the same philosophy. Make related items easy to find and let readers notice.
22. **Compulsory conclusions.** Every note ending with a universal lesson, neat resolution or promise about the future. Stop when the useful account is complete.

Punctuation is a tool, not a writing style. An em dash, a short sentence or a list of three can be appropriate. Edit the repeated habit and the unsupported meaning rather than policing a character.

## Examples from this rewrite

| Before | After |
| --- | --- |
| “Eventually, it learned one way to say yes.” | “In October 2021, I changed the answer to ‘yes,’ then fixed the array index.” |
| “Same curiosity. Another pair of hands.” | “My daughter's game, from an idea I tried in 2023.” |
| “I help with the machinery underneath.” | “I build the backend, set up hosting and help with the heavier engineering.” |
| “A pleasantly ordinary result at the end of a rather elaborate journey.” | “The extension received the URL through Google Cloud Messaging and opened it in a new tab.” |
| “A shared thread: carrying something useful into what comes next.” | “Also in the collection:” |
| “The smallest result in the system was the thing it was built to move.” | Removed. The preceding paragraph already explains the result. |

## Before publishing

- Check each factual claim against the source or the author's account.
- Give the daughter credit for game development. Keep her personal details private.
- Keep private code, data, credentials and work examples out of the page.
- Read the prose aloud. Replace anything the author would be unlikely to say.
- Check headings, captions, link labels, metadata and mobile line wrapping as well as paragraphs.
